# Gate 1 — Step 3 검수 후 수정 지시 (Step 4 진입 전)

작성 2026-10-07. Claude 독립 검수 결과. 아래 수정을 끝낸 뒤 Step 4로 간다. 이번 수정 범위 밖의 입력·조작 변경은 하지 않는다. 기존 테스트가 새 계약과 충돌하면 테스트를 새 계약으로 고치고 보고에 명시한다.

검수 방법: 소스 정독 + Godot 4.6 headless에서 별도 프로브 실행(tests/ReviewProbe.gd, 아래 수치는 그 결과). 실물 키보드·패드 체감은 검증하지 않았다.

## 반드시 (Step 4 전)

### F1. 진행 저장이 재료 추가 한 번에 깨진다
- 위치: autoload/GameState.gd `validate()` — `value["materials"].size() != known_materials.size()`이면 거부. `version != 1`도 무조건 거부.
- 재현: 지금 세이브가 있는 상태에서 materials.json에 `wing_feather`를 추가(Step 4 명세에 있음) → 실행 → save_blocked, "진행 저장 파일을 읽을 수 없습니다", 허브 진행 차단.
- 수정: `load_save()`에 마이그레이션 단계를 둔다. 데이터에 새로 생긴 재료는 0으로 채우고, 데이터에서 사라진 재료·장비·보스 id는 경고 로그를 남기고 제거한다. 장착이 사라진 장비를 가리키면 빈 슬롯으로 돌린다. 마이그레이션이 일어났으면 원본을 `.pre-migrate.bak`으로 남기고 저장한다. 구조 자체가 깨진 경우(타입 불일치, JSON 파손)만 지금처럼 차단한다.
- 테스트: 재료 하나가 빠진 세이브, 존재하지 않는 장비를 보유한 세이브 각각 로드 → 진행 가능 + 백업 생성.

### F2. 보스 id 하드코딩 제거
- 위치: Hub.gd 87(골렘 보상 문구), 141(`["golem","wing"]`), 151·182(`id == "wing"`, `id != "golem"`), GameState.gd `fresh()`/`validate()`의 `"golem"`, BattleArena.gd `"실제 게임 · 골렘"` 라벨.
- 수정: 보스 JSON에 `initially_unlocked: bool`, `order: int`를 추가(검증 포함). 허브 보스 목록·해금 초기값·보상 표시·라벨은 전부 레지스트리에서 읽는다. 전투 시작 가능 여부는 "해금됨"만으로 판단한다.
- 이 작업은 Step 4에서 날개 전용 분기를 만들지 않기 위한 선행 작업이다.

### F3. 튜닝 override 마이그레이션이 하드코딩 목록에 의존
- 위치: autoload/Tuning.gd 27~37. 새 player 키는 목록에 이름을 적어야만 보충된다. weapons 배열은 override가 통째로 대체하므로, 데이터에 새 무기가 추가되면 "장비가 참조하는 무기 누락"으로 게임 전체가 차단된다(내보낸 빌드·테스트 경로에서).
- 수정: player/feedback/training은 defaults 기준으로 빠진 키를 재귀 보충. weapons는 id 기준으로 병합(override에 없는 무기는 defaults에서 추가, 있는 무기는 빠진 필드만 보충, override 값 우선). 하드코딩 키 목록 삭제.

## 반드시 (전투 설계 결함, 수치는 사람이 최종 튜닝)

### F4. 대시 연타로 사실상 상시 무적
- 측정: 현재 수치(대시 무적 0.28, 쿨다운 0.30, 쿨다운은 대시 시작부터 카운트)에서 아래키+대시 연타 3초 동안 무적 비율 82%, 이동 거리 0px. 지상에서 아래 방향 대시는 제자리 무적이 된다.
- 수정:
  - 지상에서 대시 방향이 순수 아래(가로 성분 0)면 바라보는 방향의 수평 대시로 바꾼다.
  - 데이터 검증 규칙 추가: `dash_cooldown >= dash_iframe + min_vulnerable_gap`. `min_vulnerable_gap`은 player.json 새 키(기본 0.20). 위반 시 오류 화면이 아니라 조작감 패널 상단에 빨간 경고만 띄운다(사람이 의도적으로 넘을 수 있게).
  - player.json 기본값 제안: dash_iframe 0.20, dash_cooldown 0.45. 사람이 패널에서 다시 조절한다.
- 테스트: 연타 프로브에서 무적 비율 ≤ 50%.

### F5. 연타가 후딜을 통째로 지워 무기 차이가 사라짐
- 측정: 낡은 검, 허수아비 3초 — 공격키 유지 120 피해, 연타 320 피해(2.7배). 큐가 들어 있으면 `_tick_attack`이 후딜 시작 시점에 바로 다음 타로 넘어가서 `recovery`가 연타 시 0이 된다. 세 무기의 연타 DPS가 거의 같아진다(damage/(startup+active)가 셋 다 약 62~69).
- 수정: 각 타격 데이터에 `chain_at`(후딜 중 다음 타로 넘어갈 수 있는 시점, 후딜 시작 기준 초) 필드 추가. 큐·새 입력·방향 연계·유지 반복 모두 `action_clock >= startup + active + chain_at`일 때만 다음 타로 넘어간다. 기본값은 각 타의 recovery × 0.6. 콤보 마지막 타는 recovery 전체. 대시·패리·점프 캔슬 규칙은 그대로 둔다.
- 테스트: 같은 무기에서 유지와 연타 3초 피해 차이 ±10% 이내. 무기 패널에 chain_at 노출.

### F6. 헛패리 페널티가 없음
- 현재: 패리 판정이 끝나면 공격·점프로 후딜을 바로 끊을 수 있고 이동도 된다. 결과적으로 헛패리 비용이 쿨다운 0.4초뿐이라 패리를 아무 때나 눌러도 손해가 없다.
- 수정: 판정 후 후딜 캔슬은 "패리 성공 직후"에만 허용한다(성공 → 즉시 반격 가능, 실패 → `parry_whiff_recovery` 동안 이동·공격·점프 불가, 대시만 허용 여부는 새 키 `parry_whiff_dash_cancel` 기본 false). 기존 동작은 `parry_whiff_cancel` 키(기본 false)로 남긴다.

## 권장

### F7. 패드 스틱 드리프트가 키보드 입력을 빼앗음
- 측정: D를 누른 채로 패드 왼쪽 스틱 축 0.25 이벤트 하나 → device가 패드로 바뀌고 D를 누르고 있는데도 이동 0px.
- 수정: 축 이벤트로 장치를 전환하는 임계값을 별도 키 `device_switch_axis`(기본 0.6)로 올리고, 키보드 키가 하나라도 눌려 있으면 축 이벤트로는 전환하지 않는다. 버튼 입력은 지금처럼 즉시 전환.

### F8. 공중 공격이 쓸모없는 점프 입력에 취소됨
- 측정: 공중(점프 불가 상태)에서 공격 중 점프 키 → 공격 취소, 점프 없음.
- 수정: `attack_cancel_on_jump`는 실제로 점프가 발동할 수 있을 때(지면/코요테)만 공격을 취소한다.

### F9. 실제 게임에서 디버그 조작이 기록에 섞임
- 실제 게임 전투 중에도 무적·배속·수치 편집이 가능하고, 그 상태로 이긴 기록이 최고 시간·보상에 들어간다.
- 수정: 실제 게임 전투에서 무적·배속·튜닝 변경을 쓰면 그 런에 `debug_used`를 표시하고, 보상은 주되 최고 기록은 갱신하지 않는다. 결과 화면에 "디버그 사용" 표기. (Step 5 텔레메트리의 debug_used와 같은 플래그를 쓴다.)

### F10. 골렘 slam의 접근이 끝없이 길어질 수 있음
- move_to는 시작 시점 목적지로 180px/s 이동하고 시간 제한이 없다. 반대편 끝에 있으면 위협 없이 5~6초 걷는다.
- 수정: move_to에 선택 필드 `max_duration` 추가(초과 시 그 자리에서 다음 스텝). golem.json slam에 `max_duration: 1.5`.

### F11. 입력 버퍼가 실제 시간 기준
- attack_buffer, defense_buffer, input_edge_lifetime이 벽시계 기준이라 0.25배속·히트스톱 중에는 게임 시간 대비 버퍼가 짧아진다. 정상 배속 플레이 영향은 작지만 슬로 모드 검증이 왜곡된다.
- 수정: 플레이어 물리 delta로 감소하는 게임 시간 버퍼로 바꾼다. 포커스·메뉴·장치 전환 시 삭제 규칙은 유지.

## 하지 않을 것

새 입력 기능, 새 캔슬 규칙, UI 개편, 아트. 이번 수정 후에는 Step 4(날개) → Step 5(텔레메트리·빌드)로 바로 간다. 조작감 추가 요청은 Gate 1 판정 플레이 이후로 미룬다.
