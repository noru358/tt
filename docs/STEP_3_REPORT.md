# Step 3 및 방어 입력 수정 — 2026-10-07

## 이번 단계 결과

공격 중 패리가 씹히는 원인은 입력 어댑터 누락이 아니라, free 상태에서만 패리를 처리하며 공격/공격 유지 분기가 먼저 실행되는 행동 우선순위였다. 대시는 PARRY/HURT 상태에서 받지 않았다. 이를 하나의 방어 입력 처리 경로로 바꿨다.

- 패리·대시는 일반 공격 판단보다 먼저 처리. 공격/포션/피격 중 패리, 패리/포션/피격 중 대시를 다음 physics tick에 수용한다. 피격 취소는 패널에서 끌 수 있다.
- 대시+패리를 같은 tick에 눌러도 둘 다 실행. 대시 이동 시간과 패리 판정 시간을 별도로 유지한다. 패리가 현재 공격을 취소하고 우선한다.
- 쿨다운 종료 직전 짧은 방어 입력은 `defense_buffer=0.10초`까지만 보존. 오래 남기지 않는다. 공중 횟수 소진·기능 꺼짐 등은 예약하지 않고 이유를 표시한다. 메뉴/포커스/장치 전환 시 이력을 비운다.
- `defense_cancel_hurt=true` 및 defense_buffer를 방어·회복 패널에 노출. F키는 사용하지 않는다.
- HUD 갱신을 플레이어/보스 처리 뒤로 옮겨 같은 tick의 실제 행동을 표시한다. 대시+패리 표시와 실제 궤적/패리 원을 GPU 픽셀로 확인했다.

## 성장 루프

기본 실행은 허브다. 골렘 진입 → 승리 시 JSON 드롭 → 결과에서 허브 → 제작 → weapon/armor/charm 장착 → 재전투에 최종 스탯·무기 적용. 사망/포기는 재료·장비를 잃지 않는다.

- 재료 목록, 5개 레시피와 비용/효과·보유 표시, 부족 시 제작 비활성화, 세 슬롯 선택, 최종 스탯 요약, 보스별 처치 수/최고 시간.
- `(기본+add 합)×(1+mul 합)`을 StatCalc 한 곳에서 계산. 전투 진입 시 장비 스냅샷을 사용하며 조작감 패널 변경은 같은 계산 경로로 갱신한다.
- 완벽 회피 후 피해 버프, 포션 수 보너스, 패리 판정 보너스, 패리 회복 4개 effect 지원. 패리 OFF면 모든 효과가 패리 관련인 레시피를 데이터 기반으로 숨긴다.
- 대검/쌍단검은 이전 미리 사용 기능에 있던 데이터를 제작·장착과 연결했다. 진행 전투에서는 장착 무기를 사용한다. 자유로운 무기 미리 사용은 허브의 조작 연습으로 들어간다. 수치 편집·저장은 유지한다.
- 골렘 처치 시 날개 해금 상태를 저장한다. 날개 버튼은 해금 완료와 Step 4 전투 예정임을 구분하며, Step 3에서는 날개 전투를 시작하지 않는다.
- 진행 저장 `user://save.json`: 재료·보유·장착·해금·처치 수·최고 시간. 허브 진입/제작/장착/승리 시 저장. 임시 파일 후 교체, 직전 `.bak` 보관. 초기화는 확인 UI와 별도 `.reset-시간.bak` 보관 후 수행.
- 저장 실패 시 제작/장착 상태를 먼저 확정하지 않는다. 보상 저장 실패는 같은 보상값을 보류해 재시도하며 재추첨·중복 지급을 막는다. 손상된 원본은 자동 덮어쓰지 않고 진행을 차단·안내한다. 보류 보상은 메모리이므로 디스크 실패 상태에서 프로그램을 종료하면 복구를 보장할 수 없다.

## 코드에 남은 수치와 한계

새 조작 수치0.10초와 피격 취소 정책은 JSON. 드롭/레시피/장비/효과 수치는 기존 JSON을 읽는다. 코드 수치는 저장 버전1, 시작 보유량0·기본 검/골렘 초기 해금이라는 명세 초기 상태, 계산 항등값1, ms 변환1000, UI 좌표/폰트/레이아웃, 입력 -100→행동0→HUD100 처리 순서다. 신규 전투 밸런스 수치를 코드에 넣지 않았다.

자동 입력 검사는 키 이벤트/패드 이벤트 주입이다. 사용자의 실물 키보드 고스팅·동시입력 한계와 실물 패드 체감은 별도다. 소프트웨어에서 확인된 입력 배제 원인은 수정했고 실제 손맛·성장 동기의 평가는 사용자 재플레이가 남는다. Step 4 전투·Step 5 텔레메트리/배포는 시작하지 않는다.
