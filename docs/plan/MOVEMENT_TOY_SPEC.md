# 움직임 장난감 — Codex 설계서 (이틀 분량)

## 목적

보스 없이 작은 방 몇 개를 돌아다니는 것 자체가 재밌는지 확인한다. 완성도가 아니라 판정용이다.

판정 기준은 하나다. 목적 없이 10분 넘게 뛰어다녔는가. 이를 위해 장난감 안에서 머문 시간을 자동 기록한다.

## 범위 원칙

- 기존 프로젝트 안에 새 씬 `res://toys/movement/movement_toy.tscn`로 만든다. 보스, 허브, 장비, 세이브 코드는 건드리지 않는다.
- 플레이어는 기존 Player 씬을 그대로 쓴다. 새 동작은 Player에 추가하되 `toy_movement_enabled` 플래그가 꺼져 있으면 기존 게임 동작이 완전히 동일해야 한다.
- 그래픽은 도형. 사운드 없음.
- 수치는 전부 `res://toys/movement/movement_tuning.json`에 두고 F1 디버그 패널 슬라이더로 노출한다. 코드에 수치를 박지 않는다.

## 추가 동작

### 1. 벽 미끄러짐 / 벽 점프
- 공중에서 벽에 붙고 그 방향 입력 중이면 낙하 속도를 `wall_slide_speed`로 제한.
- 벽에 붙은 상태에서 점프 → 벽 반대 방향으로 `wall_jump_push_x`, 위로 `wall_jump_push_y`. 벽 점프 직후 `wall_jump_lock_time` 동안 수평 입력 영향 감소(벽으로 즉시 돌아붙는 것 방지).
- 벽 점프 후 대시 1회 재충전.

### 2. 튕기기 (핵심 동사)
오리의 배시와 같은 계열이다.
- 튕기기 대상(Bashable) 근처 `bash_radius` 안에서 튕기기 버튼을 누르고 있으면 게임 속도가 `bash_time_scale`로 느려지고, 대상 중심에 조준 화살표가 뜬다.
- 조준은 패드 왼쪽 스틱 또는 키보드 방향키. 8방향이 아니라 연속 각도.
- 버튼을 떼면 플레이어는 조준 방향으로 `bash_launch_speed`로 발사되고, 대상은 반대 방향으로 밀려난다(투사체라면 반대 방향으로 날아가며 적에게 피해).
- 느린 시간은 최대 `bash_max_hold` 초. 넘으면 자동 발사.
- 발사 직후 `bash_air_control_delay` 동안 수평 입력 영향 감소, 이후 정상 공중 제어.
- 튕기기 후 대시와 2단 점프(있다면) 재충전. 같은 대상은 `bash_same_target_cooldown` 동안 재사용 불가.
- 가장 가까운 대상 하나만 잡는다. 범위 안에 대상이 있으면 대상 외곽선이 밝아진다.

## 튕기기 대상 3종

- `o` 고정 구슬: 공중에 떠 있다. 튕기면 밀려났다가 `orb_return_time` 동안 원위치로 돌아온다.
- `m` 움직이는 구슬: 좌우로 `moving_orb_range` 칸 왕복.
- `T` 포탑: 벽에 붙어 일정 간격(`turret_interval`)으로 직선 투사체를 쏜다. 투사체에 맞으면 피해, 튕기면 반대로 날아간다. 포탑 자체는 튕기기 대상이 아니다. 투사체 방향은 방 파일의 포탑 옆 화살표 문자로 정한다(아래 범례).

## 방 파일 (가장 중요)

방은 텍스트 파일 하나다. 사람이 메모장으로 한 글자 바꾸고 바로 확인할 수 있어야 한다.

위치: `res://toys/movement/rooms/room_01.txt` … 파일명 순서대로 이어진다.

타일 크기는 `tile_size`(기본 32px). 행 길이가 달라도 짧은 행은 오른쪽을 빈칸으로 채워 읽는다. 모르는 문자는 빈칸으로 처리하고 콘솔에 경고(행, 열, 문자)를 남긴다.

범례:
```
#  벽/바닥
=  한쪽 통과 발판 (아래에서 위로 통과)
.  빈칸 (공백도 빈칸)
P  시작 위치
C  체크포인트 (닿으면 활성, 죽으면 여기서 부활)
^  가시 (닿으면 즉시 마지막 체크포인트로, 0.3초 페이드)
o  고정 구슬
m  움직이는 구슬
T  포탑. 바로 오른쪽 칸 문자가 발사 방향: < > A V (그 칸은 빈칸 취급)
G  목표. 닿으면 다음 방으로
```

카메라는 플레이어를 부드럽게 따라가고 방 경계 밖은 보여주지 않는다.

### 단축키
- F7: 현재 방 파일 다시 읽기(플레이어는 마지막 체크포인트로). 에디터 실행 기준이며, 파일 수정 후 게임을 끄지 않고 반영되는 것이 완료 조건이다.
- F8 / Shift+F8: 다음 방 / 이전 방.
- F1, F2, F5, F6은 기존 그대로(튜닝 패널, 판정 박스, 무적, 속도).
- 기존 F2 판정 박스 표시 시 `bash_radius` 원도 함께 표시.

## 시간 기록

`user://toy_movement_log.jsonl`에 세션 종료 시 한 줄:
```json
{"started_at": "...", "duration_sec": 0, "rooms_entered": [], "deaths": 0, "bash_count": 0, "wall_jump_count": 0, "f7_reloads": 0}
```
`f7_reloads`는 사람이 방을 고친 횟수다. 노는 시간과 고치는 시간을 구분하기 위해 남긴다.

## 완료 조건

1. 4개 방을 끝까지 갈 수 있다(F5 무적 없이 도달 가능한지 직접 확인하고 보고. 못 가는 방이 있으면 수치나 방 어디가 문제인지 적는다).
2. 방 파일에서 구슬 하나를 옮기고 F7을 누르면 게임을 끄지 않고 반영된다.
3. 행 길이가 다른 방 파일, 모르는 문자가 섞인 방 파일을 넣어도 죽지 않고 경고만 남긴다.
4. `toy_movement_enabled`를 끄면 기존 골렘·날개 전투에서 플레이어 동작이 이전과 같다.
5. 세션 종료 후 로그 한 줄이 정확히 남는다.
6. F1 패널에서 튕기기 수치를 바꾸면 즉시 반영되고 저장 후 재실행해도 유지된다.

## 하지 않는 것

아트, 사운드, 적, 보스, 맵 연결 구조(메트로배니아식 지도), 능력 해금, 수집품, 레벨 에디터 UI, 요청받지 않은 리팩터링.

## 보고 형식

기존 gate1-spec과 같다. 한 것, 수정·생성 파일과 이유, 완료 조건별 확인 결과(못 한 건 못 했다고), 코드에 남은 수치, 사람이 정해야 할 것.
