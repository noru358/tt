## 수정·생성 파일과 이유

- `scripts/player/Player.gd`: export 플래그와 구성요소 참조, 플래그가 켜질 때만 물리 처리 위임. 꺼진 경로의 기존 구현은 그대로.

- `ToyMotion.gd`: 벽 동작·배시·대시·시간 복구·입력 처리.

- `movement_tuning.json`, `movement_schema.json`: 모든 추가 게임플레이 수치와 유효 범위/슬라이더 단계. 원문 초기 15개 값 유지.
- `rooms/room_01.txt`~`room_04.txt`: 원문 초안 그대로.
- `tests/MovementToySuite.*`: 기능 27개 검사. 방/수치 파일 변경 검사는 MOVEMENT_TEST_ROOMS/TUNING 외부 scratch 필수.
- `tests/MovementRouteProbe.*`: 물리 시뮬레이션 경로 시도. 실제 사람 조작 검증 아님.
- `tests/MovementVisualProbe.*`: GPU 캡처·재시작 로딩 확인.
- `RunMovement.command`, `RunMovement.cmd`, `MOVEMENT_README.md`: 장난감 직접 실행 및 조작 설명.
- `docs/evidence/movement/*`, 이 보고서, WORK_LOG: 확인 증거 및 한계.

## 코드에 남은 수치

게임플레이 수치는 movement_tuning.json, 슬라이더 범위/단계는 movement_schema.json에 있다. 기존 Player._begin_dash에서 기존 수치를 먼저 읽은 뒤 장난감 JSON의 거리/시간/쿨다운으로 덮어쓴다. 기존 Player의 체력 및 본체 기본 도형/대시 잔상은 기존 data JSON/그리기 코드에서 재사용한다.

추가 코드의 고정 수치는 UI·도형용: 패널 위치(20,150)/크기(700,650)/목록폭650, HUD(20,16), 포탑 도형20px/반폭10/총구20/선3, 외곽선 여백3/선2/32분할, 범위64분할/선1, 화살촉12px/0.5rad/선3. 색상도 코드에 있다. 수학용 0/1/2, TAU, 밀리초↔초1000, 분60000, 나눗셈 보호0.00001, 입력키·레이어 비트값은 고정이다. 새 물리 감각 수치를 숨겨 하드코딩하지 않았다.
