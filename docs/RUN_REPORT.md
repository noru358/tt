# 한 판(점프 방 + 골렘) 보고 — 2026-10-09

사용자 결정: 골렘 다음은 "한 판으로 합치기". 점프맵 방 몇 개를 지나 마지막 골(G)에 닿으면 골렘 방으로 넘어가는 한 판을 만들었다.

## 실행

- **기본 게임이 한 판이다(최종 통합, 같은 날).** Mac `Run.command`(또는 `RunOneRun.command`), Windows `Run.cmd`(또는 `RunOneRun.cmd`), 에디터 F5. 프로젝트 기본 씬이 `res://toys/run/run_toy.tscn`.
- 점프 방만: `RunMovement.command`/`.cmd`(인자 없으면 점프 장난감). 골렘만: `RunGolemBash`.
- 방 목록은 `toys/run/run.json`(기본: room_01 → room_08 전부). 파일만 고치면 순서와 개수가 바뀐다.
- 1~4번 방은 통일 이동 수치로 자동 경로 확인을 못 했다. 기존 경로 봇(`MovementRouteProbe`)은 이전 수치에서도 1·3·4번을 못 깨는 낡은 봇이라 판단 근거가 안 된다. 5~8번은 방 묶음 2 봇으로 통과.

## 이동 수치 통일 (사용자 결정, 같은 날)

점프맵과 골렘방을 같은 수치로 맞췄다. `movement_tuning.json` 자체를 바꿨고(점프 장난감도 이 값), 골렘 쪽 `boss_*` 덮어쓰기는 없앴다.

| 수치 | 점프맵(이전) | 보스방(이전) | 통일 |
|---|---|---|---|
| 달리기 | 260 | 200 | 230 |
| 점프 속도 / 중력 | 430 / 1050 | 470 / 1350 | 450 / 1200 |
| 최대 낙하 | 700 | 750 | 725 |
| 가속 | 1600 | 1100 | 1350 |
| 대시 거리 / 시간 | 150 / 0.20 | 110 / 0.16 | 130 / 0.18 |
| 공중 대시 | 2 | 2 | 2 |
| 대시 끝난 뒤 남는 속도 | 100% | 30% | 65% (`dash_end_keep`, ToyMotion에 추가) |

- 포고 320 → 280, 약점 판정 반지름 24 → 34(그림 크기는 그대로, F2 판정 보기의 분홍 원이 실제 판정).
- 바뀐 이동에 맞춘 방 수정: 5번 방은 우물 아래쪽 직선 구간 4줄을 줄이고, 골 선반을 한 줄 내리고 넓혀 골을 2칸 높이로(날아서 지나가도 닿게). 7번 방은 두 발판을 2칸씩 넓혔다. 6·8번은 그대로 통과.
- 검사 변경: 방 검사의 "골 1개"를 "골 1개 이상(세로로 이어진 칸 허용)"으로, 5번 방 자동 봇의 목표 좌표를 새 골 위치로.

## 규칙

- 점프 구간: 움직임 장난감 그대로(가시에 죽으면 체크포인트로). 마지막 방의 골에 닿으면 골렘 방으로 넘어간다.
- 골렘 구간: 골렘 튕기기 장난감 그대로, 이동 수치는 점프 구간과 같다. 골렘에게 죽으면 첫 방이 아니라 골렘부터 다시.
- 이기면 결과 창에 "한 판 클리어! 총 시간 (점프 · 골렘, 몇 번째 도전)".
- 로그: 한 판마다 `user://toy_run_log.jsonl`에 한 줄(result clear/quit, 어디까지 갔는지, 총 시간, 골렘 시간, 골렘 도전 횟수). 점프 장난감과 골렘 장난감 로그도 각자 그대로 쌓인다.
